# Running the Kiwi Hardware Control Simulation Stack

This document outlines the steps to build and run the full simulation stack, which includes the hardware simulator (`hw_sim`), GC (Global Counter), and QBER (Quantum Bit Error Rate) programs for both Alice and Bob.

## Prerequisites

1.  **Rust Toolchain**: Ensure you have Rust installed to build the `hw_sim`. You can get it from [rustup.rs](https://rustup.rs/).
2.  **Kiwi Hardware Control Programs**: The `gc` and `qberr` programs, as well as the `run_local.sh` script, are expected to be in a directory relative to this `hw_sim` project, specifically `../kiwi_hw_control/`.
3.  **Dependencies for `gc` and `qberr`**: Ensure any dependencies for the `gc` and `qberr` programs are met. (This document does not cover their specific build process).

## 1. Build the Hardware Simulator (`hw_sim`)

The `hw_sim` is the Rust application in the current project directory.

Navigate to the root directory of the `hw_sim` Rust project (where this `README_STACK.md` is located) and run the following command to build it:

```bash
cargo build --release
```
This will create an optimized executable at `target/release/hw_sim`. For debugging, you can use `cargo build` which creates an executable at `target/debug/hw_sim`. The `run_local.sh` script might assume one of these paths.

## 2. Run the Full Stack using `run_local.sh`

The `../kiwi_hw_control/run_local.sh` script is designed to orchestrate all components of the simulation.

To run the entire stack:

1.  **Navigate to the `kiwi_hw_control` directory**:
    ```bash
    cd ../kiwi_hw_control
    ```

2.  **Execute the `run_local.sh` script**:
    ```bash
    ./run_local.sh
    ```

### What `run_local.sh` Does:

Based on your description and logs, the `run_local.sh` script typically performs the following actions:

*   **Starts Bob's components**:
    *   `gc_bob`: Bob's Global Counter client program.
    *   `qber_bob`: Bob's QBER program.
    *   `hw_sim` (for Bob): An instance of the hardware simulator configured in **Detector** mode, using a specific configuration file (e.g., `config_bob.json`).
*   **Starts Alice's components**:
    *   `gc_alice`: Alice's Global Counter program.
    *   `qber_alice`: Alice's QBER program.
    *   `hw_sim` (for Alice): An instance of the hardware simulator configured in **Source** mode, using a specific configuration file (e.g., `config_alice.json`).

The script manages the necessary inter-process communication setup (like FIFOs and mock MMIO files, e.g., `/tmp/sim_alice_cmd.s`, `/tmp/sim_bob_cmd.s`) that the `hw_sim` instances expect.

## 3. Understanding `hw_sim` Configuration

The `hw_sim` executable (e.g., `target/release/hw_sim`) typically accepts command-line arguments to specify its behavior:

*   `--conf <path_to_config.json>`: Specifies the main configuration file for the simulator. This file, in turn, points to backend and IPC configurations.
*   `--mode <Source|Detector>`: Sets the operational mode of the simulator.
*   `--logs-location <path_to_logs_directory>`: (Optional) Specifies where log files should be stored. Defaults to a local `logs` directory.

The `run_local.sh` script is responsible for invoking `hw_sim` with the correct arguments for both Alice's and Bob's instances. For example:

```bash
# Example invocation for Alice (likely done within run_local.sh)
# Assumes hw_sim is in a known location relative to the script or in PATH
path/to/hw_sim --conf path/to/config_alice.json --mode Source

# Example invocation for Bob (likely done within run_local.sh)
path/to/hw_sim --conf path/to/config_bob.json --mode Detector
```

## Troubleshooting

*   **File Not Found Errors**: If you see errors like `No such file or directory` for files in `/tmp/` (e.g., `/tmp/sim_alice_cmd.s`), ensure the `hw_sim` has the correct logic to create these mock files when using `/tmp/` paths in its IPC configuration. The `setup_ipc_fifos` function in `src/ipc/config.rs` is responsible for this.
*   **Permissions**: Ensure the `run_local.sh` script has execute permissions (`chmod +x run_local.sh`).
*   **Relative Paths**: The `run_local.sh` script likely relies on relative paths. Ensure you run it from the correct directory (`../kiwi_hw_control/`).
*   **Log Files**: Check the log files generated by `hw_sim` (e.g., in `logs/` or the directory specified by `--logs-location`) and any logs produced by `gc` or `qberr` for more detailed error information.
